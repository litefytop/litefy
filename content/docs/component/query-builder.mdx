## Usage

`QueryBuilder` renders the query as a **tree with two node types**: field nodes and group nodes. Every field appears **exactly once** per group — a field folder with several sub-conditions replaces repeating the same field row after row. The layout is fully recursive: the root group and every added group share the same first row — collapse chevron, **AND / OR** segment and the **+ Group** button — above a guide-line indented body that scrolls inside a fixed-height frame. Below it, a read-only **preview panel** shows the query in natural language by default, and centered **Submit / Reset** buttons sit at the very bottom.

<ComponentPreview name="query-builder-basic" />

- **text / number / date** — expand the field folder and press **+ Condition** to add sub-conditions; each sub-condition is an operator dropdown plus a value input.
- **Group** — a nested root: exactly the same layout as the root group — same first row, same folder list — so nesting reads as one recursive pattern.

### Enum fields

`valueKind: "select"` fields expand to a checkbox list with a **select-all** checkbox. Checking and unchecking options directly creates and removes the condition; the checked options merge into a **single `IN` condition** (never split into `OR`ed equals). Only forward `IN` is offered — no `NOT IN`; to invert a selection, check everything and uncheck what you don't need.

### Submit and Reset

The tree is a draft: edits update the live preview only. The preview defaults to **natural language** ("Name contains …"), built from field labels so it reads for humans; switch it to SQL, MongoDB, CEL and more with the format selector. **Submit** emits the query tree through `onSubmit` / `onQueryChange` in the react-querybuilder `RuleGroupType` format — hand it to `formatQuery` for those same transformations, and `parseSQL` hydrates a stored condition string back through `defaultValue`. **Reset** restores the draft to `defaultValue` (or an empty tree).

## API Reference

### QueryBuilder

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `fields` | `QueryFieldConfig[]` | - | Available fields; each renders as one unique folder node. **Required** |
| `defaultValue` | `RuleGroupType` | empty `and` tree | Initial query (react-querybuilder format); also what Reset restores |
| `onSubmit` | `(query: RuleGroupType) => void` | - | Fired by the Submit button |
| `onQueryChange` | `(query: RuleGroupType) => void` | - | Alias of `onSubmit` |
| `onReset` | `() => void` | - | Fired by the Reset button |
| `showPreview` | `boolean` | `true` | Show the read-only logic-expression preview panel |
| `showConvert` | `boolean` | `true` | Show the format selector inside the preview panel |
| `convertFormats` | `string[]` | `natural_language, sql, parameterized, parameterized_named, mongodb, cel, spel, json, jsonlogic` | Formats offered by the selector |
| `maxDepth` | `number` | `2` | Maximum group nesting depth |
| `disabled` | `boolean` | `false` | Disable the builder |
| `className` | `ClassNameValue` | - | Custom classes, applied to the root |

### QueryFieldConfig

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `name` | `string` | - | Field identifier written into the query. **Required** |
| `label` | `string` | `name` | Field label shown on its folder node |
| `operators` | `string[]` | per `valueKind` | Operators offered for sub-conditions |
| `valueKind` | `"text" \| "number" \| "date" \| "select"` | `"text"` | Value editor type |
| `options` | `{ label, value }[]` | - | Options when `valueKind: "select"` |

### Security: the query leaves as JSON, never as SQL

`onSubmit` / `onQueryChange` hand you the **structured query object** — never a SQL string. The dialect previews (SQL / MongoDB / CEL / Natural Language) are **display-only**, rendered in the browser for human reading. Do not send those strings to your backend for execution: client-generated SQL cannot be trusted or safely validated, and executing it would bypass parameterization as well as any row-level scoping.

The safe backend flow is: receive the JSON object → validate it against a whitelist (allowed fields, allowed operators per field, value types and ranges) → convert it to **parameterized** SQL server-side, binding every value as a query parameter. The frontend's job is the editing experience; dialect correctness and safety both belong to the backend.

`@react-querybuilder/core` stays a display dependency of this component — if your backend wants the same conversion, implement it server-side from the emitted JSON.
