## Usage

Items are balanced across equal-width columns; the column count responds to container width by default (`1 / sm:2 / lg:3 / xl:4`).

## API Reference

### High-level Components

#### Masonry

A data-driven masonry layout; async content that grows taller after mount is not re-measured automatically — give it a min-height close to its final size.

| Prop         | Type                                                    | Description                                                                                                                                                                                                                                               |
| :----------- | :------------------------------------------------------ | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `items`      | `T[]`                                                   | The data list                                                                                                                                                                                                                                             |
| `renderItem` | `(item: T, index: number) => React.ReactNode`           | Renders a single cell                                                                                                                                                                                                                                     |
| `getKey`     | `(item: T, index: number) => React.Key`                 | Stable key per item; also drives the internal measurement cache, defaults to index                                                                                                                                                                        |
| `columns`    | `number \| { base?; sm?; md?; lg?; xl?; 2xl? }`         | Fixed column count, or breakpoint columns resolved from container width (resolved in JS, sm 640 / md 768 / lg 1024 / xl 1280 / 2xl 1536) — balanced lanes and nested lanes read the same breakpoint table, defaults to `{ base: 1, sm: 2, lg: 3, xl: 4 }` |
| `className`  | `string`                                                | Custom class name for the root element. Gap is not a class: the skeleton writes inline spacing from `--litefy-masonry-gap`, a token defined by the current scheme; change the gap per instance via `styles.column` / `styles.item`                        |
| `classNames` | `{ column?; item? }` — all values `string`              | Custom class names for each part                                                                                                                                                                                                                          |
| `styles`     | `{ column?; item? }` — all values `React.CSSProperties` | Inline styles for each part                                                                                                                                                                                                                               |

### Composable Components

#### MasonryColumn

The equal-width column container — the skeleton gives it inline `display: flex; flex-direction: column; flex: 1 1 0%; min-width: 0` with spacing `gap: var(--litefy-masonry-gap, 1rem)`, so the column layout holds even when the scheme misses its styles.

| Prop       | Type                          | Description             |
| :--------- | :---------------------------- | :---------------------- |
| `className`| `string`                      | Custom class name       |
| `...props` | `React.ComponentProps<"div">` | Supports all native div props |

#### MasonryItem

The cell wrapper each item renders into; the skeleton gives it inline `min-width: 0`, and the static (nested) lane adds `margin-bottom: var(--litefy-masonry-gap, 1rem)` and `break-inside: avoid`.

| Prop       | Type                          | Description             |
| :--------- | :---------------------------- | :---------------------- |
| `className`| `string`                      | Custom class name       |
| `...props` | `React.ComponentProps<"div">` | Supports all native div props |

## Keyboard Interactions

This component takes over no keys — no part attaches key handlers; focus and keys belong to whatever `renderItem` puts inside the cells.

## Data Attributes

| Attribute             | Description                                                                                                                                                         |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `[data-masonry-key]`  | On each item wrapper in the measured lane — the item's key, i.e. the string result of `getKey(item, index)` or the index itself; the round that assigns heights looks items up by it |
| `[data-masonry-index]` | On the same wrapper — the item's index in `items`; its `offsetHeight` is recorded into the height slot for that index                                               |

The static lane (the layer nested inside another `Masonry`) emits neither attribute, because it does no height balancing.
