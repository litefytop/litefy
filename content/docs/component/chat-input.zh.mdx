Chat Input 不是一个提供源码的组件。它的核心是[Textarea](/docs/component/text-area) 保持纯粹的承诺：粘贴、预览、按钮全部在业务侧拼装。`Textarea` 的 props 透传原生 `onPaste`，在事件里读取 `clipboardData` 即可拿到截图文件；图片预览渲染在 Textarea 外部的缩略图条（`<textarea>` 无法在文本流内显示图片，这是组合方案的天然边界）；按钮栏是普通的 flex 布局。直接在页面中拼装即可 —— 下面的示例就是完整的实现。

拼装要点：

- 截图粘贴：在 `onPaste` 里过滤 `clipboardData.items` 中 `type` 以 `image/` 开头的文件项，`e.preventDefault()` 阻止图片以路径形式落入文本；文本粘贴不受影响（无图片时提前返回）。
- 预览条：`URL.createObjectURL(file)` 生成缩略图地址，删除或发送时 `URL.revokeObjectURL` 释放内存。
- 底部按钮栏：与 Textarea 平级的 flex 行，左侧是 [Toggle](/docs/component/toggle) 能力开关（深度思考、联网搜索），右侧发送按钮；发送条件为「有文本或有截图」。
- `Textarea` 通过 `className` 覆盖为无边框无阴影（`border-0 shadow-none focus:ring-0`），视觉上融入外层容器，外层容器负责整体边框。
- Enter 发送、草稿、@提及等行为同样属于业务层，按需在 `onKeyDown` 中扩展，组件本身不参与。
