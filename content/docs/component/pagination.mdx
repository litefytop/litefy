## API Reference

### High-level Components

Ready-to-use composite components.

#### Pagination

| Prop           | Type                                                      | Description                                                                                                                                   |
| -------------- | --------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `page`         | `number`                                                  | Current page (1-based). **Required**                                                                                                          |
| `totalPages`   | `number`                                                  | Total number of pages. **Required**                                                                                                           |
| `onPageChange` | `(page: number) => void`                                  | Fired when any button is clicked                                                                                                              |
| `siblingCount` | `number`                                                  | Number of page numbers shown on each side of the current page; the rest collapse into ellipsis, defaults to `1`                                 |
| `summary`      | `React.ReactNode`                                         | Pagination summary text slot; omit it to leave this row unrendered                                                                            |
| `className`    | `string`                                                  | Custom class name, applied to the root `nav`                                                                                                 |
| `classNames`   | `{ controls?, nav?, boundary?, pages?, page?, ellipsis?, summary?, pageInput?, pageTotal? }` | Custom class name per part: `nav` applies to previous / next, `boundary` to first / last, `pageInput` to the page input and `pageTotal` to the total page count; `nav` and `boundary` receive `({ disabled }) => string`, which is `true` at the first/last boundaries, while the remaining slots take fixed class names |
| `styles`       | The same nine keys as `classNames`                        | Custom inline styles for the same parts                                                                                                       |

The form switches between two variants based on the pagination bar's own available width, decided by a container query with no form prop; whether it stays on one line or wraps to two depends on actual flex-wrap fit, not the variant width:

| Available width | Content shown |
| ------------- | --------------------------------------------------------------------- |
| `< 48rem`     | First, previous, page input, total page count, next, last (measured at 283px) |
| `≥ 48rem`     | Previous, page numbers (with ellipsis), next (measured at 304px at the edges and 460px in the middle); first and last are covered by the page list's endpoints, while the page input and total page count leave |

- Width is based on the pagination bar's container, not the viewport: place it in a 40rem card and it selects that variant.
- When the summary and controls cannot fit on one line, the summary moves as a whole block to the first line and the controls occupy the second; a summary longer than its container wraps so it can be read in full. Neither path clips text, so neither uses `title` — `title` is unavailable to touch and keyboard channels and cannot be a fallback for clipped text.
- When the container is narrower than the controls (< 283px), navigation buttons wrap inside the cluster without shrinking their 44px hit areas or overflowing horizontally.
- Controls in the hidden variant are absent from the focus order and accessibility tree, so only one set of controls is interactive at a time.
- Each +1 to `siblingCount` widens the page-number list by 104px (measured): the `48rem` variant only guarantees that `siblingCount = 1` shares a line with the summary; using `2` on the same line needs a container of at least 876px, otherwise the summary follows the second wrapping path.
- The documentation site's content column measures 590px and always selects the page-input variant; to see page numbers, place the pagination bar in a container at least 48rem wide (such as a full-width table).

### Composable Components

| Part | Element | Emitted attributes | Description |
|------|------|--------|------|
| `PaginationRoot` | `<nav>` | `aria-label="pagination"` | Row container |
| `PaginationFirst` | `Button` | `aria-label="First page"` | Jump to the first page (`ChevronsLeft`) |
| `PaginationPrev` | `Button` | `aria-label="Previous page"` | Previous page (`ChevronLeft`) |
| `PaginationPages` | `<div>` | - | Page-number buttons + ellipsis |
| `PaginationNext` | `Button` | `aria-label="Next page"` | Next page (`ChevronRight`) |
| `PaginationLast` | `Button` | `aria-label="Last page"` | Jump to the last page (`ChevronsRight`) |
| `PaginationEllipsis` | `<span>` | - | Collapsed pages marker (`MoreHorizontal`) |
| `PaginationSummary` | `<span>` | - | Summary text slot |

The total page count (`/ 12`) is a `<span>` rendered internally by the composite through the `classNames.pageTotal` slot, not `PaginationSummary`; the page input likewise uses `classNames.pageInput`.

The current page number carries `aria-current="page"`. Navigation buttons at the first/last boundaries are natively `disabled`, use `text-disabled-fg` and `cursor-not-allowed`, and no longer respond to clicks or enter the tab order.

## Keyboard Interactions

The skeleton attaches no key handlers except on the page input. Every button is a native `<button type="button">`; key behavior belongs to HTML itself.

| Key | Description |
| --- | --- |
| `Tab` | Reaches visible controls in DOM order: first, previous, page-number buttons (`≥ 48rem`) or the page input (`< 48rem`), next, last. Pages collapsed into ellipsis, controls hidden by the active variant, and buttons at the first/last boundaries are not in the tab order |
| `Enter` / `Space` | Natively activates the focused button; every button fires `onPageChange` once |
| `Enter` | Submits the page in the page input; out-of-range or non-numeric input falls back to the current page, and blur also submits |

## Data Attributes

| Attribute | Description |
| --- | --- |
| `[data-pure-icon]` | On the first, previous, next and last buttons — their content is a single icon without text (from [Button](/en/docs/component/button)) |

The `nav`, `boundary`, pages container, ellipsis, page input and pagination text carry no `data-*`; the current page is marked by `aria-current="page"`, not by a data attribute.
