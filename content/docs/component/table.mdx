## Usage

A data-driven table: pass `data` and `columns`; `sortable: true` enables sorting, `selectable` enables row selection. Columns compress by weight with a 64px floor per column; overflow scrolls.

<ComponentPreview name="table-basic" />

### Remote sorting

Pass controlled `sort` + `onSortChange` to enter remote mode, delegating sorting to your database; pair with [useRemoteSort](/en/docs/utils/use-remote-sort) to manage the state.

<ComponentPreview name="table-remote" />

### Row selection

`selectable` enables row selection: the first column is a square checkbox column as wide as the row height (44px), plus a tri-state select-all for the page; the selection key comes from `rowKey`, and selections persist across pages. Clicking anywhere in a row also toggles it (clicks on checkboxes, links, buttons and other interactive elements are excluded); the checkbox remains the keyboard path. The table never renders a second row — echo the count and actions (e.g. `3 selected` + a clear button) in the [Pagination](/en/docs/component/pagination) `summary` slot placed under the table.

<ComponentPreview name="table-selectable" />

### Zebra striping

`zebra` shades odd rows by data order — the pattern stays correct through sorting and virtualization.

<ComponentPreview name="table-zebra" />

### Virtual scrolling

`virtual` renders only the visible window for large datasets; `rowHeight` must match the rendered row stride (defaults to `45`: the 44px control-height row plus the 1px divider). Rows must stay single-line — wrapped content changes the row height and desynchronizes the window. Scrolling happens inside the body — x-axis scrolling lives on the table root, the body scrolls y only and owns the scrollbar; the scrollbar look is defined globally by the loaded scheme and is always visible, components never touch it.

<ComponentPreview name="table-virtual" />

### Column reordering

`columnDrag` makes headers draggable to reorder columns; the selection column stays first and is never dragged. Pointer: drag a header onto another. Keyboard: focus the handle button, press `Enter` to pick up, move with the arrow keys, `Enter` to drop, `Escape` to cancel. Order is controlled via `columnOrder` + `onColumnsChange`, or uncontrolled via `defaultColumnOrder`; keys missing from the order keep their original relative order at the tail.

<ComponentPreview name="table-column-drag" />

### Cell text collapse

Columns with `collapse: true` collapse their cell content to a single ellipsized line with a native `title` tooltip (shown only while truncated); clicking fully expands the content and it does not collapse back. The first render never shifts layout; expanding changes the row height, which conflicts with the fixed-height constraint of `virtual` — do not enable it on expandable rows in virtual tables. Customize the collapsed cell via `classNames.cellCollapse`.

<ComponentPreview name="table-collapse" />

### Filtering belongs to the business layer

The skeleton ships no filtering: filter controls depend heavily on the column type (text, enum, number and date each need a different value control), which does not fit one generic API. When you need filtering, build your own row via the `headExtra` slot at the tail of the header, compose it from primitives like [Input](/en/docs/component/input), [Select](/en/docs/component/select) and [Date Picker](/en/docs/component/date-picker), filter the data on the business side, and pass the result back as `data`.

#### TableColumn&lt;T&gt;

| Field       | Type                            | Description                                                                            |
| ----------- | ------------------------------- | -------------------------------------------------------------------------------------- |
| `key`       | `keyof T & string`              | Row field to display **Required**                                                      |
| `header`    | `React.ReactNode`               | Header label; a string header also becomes the cell's `data-label`, defaults to `key`  |

| `sortable`  | `boolean`                       | Make the header click-to-sort, defaults to `false`                                     |
| `compare`   | `(a: T, b: T) => number`        | Custom comparator used by local sorting, defaults to `<` / `>`                         |
| `align`     | `"left" \| "right" \| "center"` | Cell alignment; the design spec keeps columns start-aligned (center is fine for control columns), defaults to `"left"` |
| `span`      | `number`                        | Width weight: the column's share of the container width = its own `span` ÷ the sum of data columns' `span` (the selection column is excluded — it is fixed at 44px); columns keep this exact proportion regardless of content or paging, defaults to `1` |

| `className` | `string`                        | Custom classes applied to the column's header cell and body cells (your own layout, e.g. truncating long text) |

### Composable Components

| Part | Element | Emitted attributes | Description |
|------|---------|--------------------|-------------|
| `TableRoot` | `<div>` | - | Outer frame — horizontal scroll fallback for hand-assembled wide content |
| `TableHead` | `<div>` | - | Header strip; never scrolls |
| `TableBody` | `<div>` | - | Body scroller |
| `TableBase` | `<table>` | - | The table element rendered by the header strip and by the body (built-in `table-layout: fixed`) |

All parts accept native element props plus `className`. Head and body are two separate tables sharing one `<colgroup>`, so column widths never depend on the row count and paging never shifts the layout; the default body height and every other visual are defined by the loaded scheme. Scroll contract: the root is the only horizontal scroll container (it never scrolls y), the body scrolls y only and owns the scrollbar; head and body containers get a `min-width` of the summed column floors, so when the floors exceed the container both grow to the same width and the root scrolls horizontally. Scrollbar styling is defined globally by the scheme and always visible — components never set scrollbar styles. Hand-assembled tables must keep the `<colgroup>` identical to what `Table` emits (`width: max(64px, calc(span * 100% / total span))` on every `<col>`; with `selectable`, the selection column is fixed at `44px` and data columns split the remaining width).

## Keyboard Interactions

| Key | Description |
| --- | --- |
| `Tab` | Reaches the row checkboxes (`selectable`), the drag handles (`columnDrag`), and focusable elements you render inside `render` or `header` |
| `Enter` / `Space` | On a drag handle — pick up the column; press again to drop |
| `ArrowLeft` / `ArrowRight` | While a column is picked up — swap it with the adjacent column |
| `Escape` | While a column is picked up — cancel and restore the pre-grab order |

Sorting is bound to `onClick` on a `<th>`, which is not focusable — for keyboard sorting put your own `<button>` in `header`. Row selection keeps the row checkbox as its keyboard path.

## Data Attributes

| Attribute | Description |
| --- | --- |
| `[data-sortable]` | On a header cell — present when the column is `sortable` |
| `[data-sorted]` | On a header cell — present when its column is the current sort key |
| `[data-active]` | On the sort icon — present on the sorted column's icon |
| `[data-align]` | On header and body cells — `"left"`, `"center"` or `"right"`, matching the column's `align` |
| `[data-drag-over]` | On a header cell — present while a dragged column hovers over it (`columnDrag`) |
| `[data-grabbed]` | On the drag handle — present while its column is picked up via keyboard |
| `[data-label]` | On body cells — the column's string `header`, used as the cell's label |
| `[data-selectable]` | On body rows — present when `selectable`; rows are click-to-toggle |
| `[data-zebra="odd"]` | On body rows — present on odd data rows when `zebra` |
| `[data-selection-cell]` | On body cells — marks the selection column's cell, excluded from row-click toggling |
