Transfer Picker is not a shipped component with source code. It is a composition of existing primitives: a two-column transfer layout where the left side is a remote-search `Input + List` (the Combobox assembly), and chosen values move to the right-side selected list where they can be batch-removed. Assemble it directly in your page — each demo below is the complete implementation.

It exists because of data volume. Grouped [MultiSelect](/docs/component/multi-select) fits known, enumerable datasets (e.g. cities); when data lives on a server with unknown size, grouping is meaningless and typing-to-search is the only viable filtering — so the left panel is a remote list and never renders groups.

## Usage

### Two-column Select

The plain variant: clicking an item or pressing `Enter` toggles it into the right panel, and selected items are marked with a check in the left list.

<ComponentPreview
  name="transfer-picker-basic"
/>

Key points of the assembly:

- The left panel pairs a controlled [Input](/docs/component/input) with a [List](/docs/component/list) driven by the `useRemotePagination` hook: typing debounces `remote.search`, scrolling to the bottom calls `remote.loadMore`, and keyboard navigation uses the controlled `highlightIndex` pattern (focus stays on the input, `ArrowDown`/`ArrowUp` move the highlight, `Enter` confirms).
- The right panel lists selected values as [Checkbox](/docs/component/checkbox) items; the header checkbox check-alls, and the `Remove` button batch-deletes the checked ones — mirroring the transfer's multi-select-and-move-back interaction.
- The left list intentionally has no grouping — with server-side data of unknown size, grouping is meaningless once the user is filtering by text.

### Two-column Multi-select

The counted variant: each right-panel entry carries a count adjusted by an embedded `NumberField`, so the same value cannot be duplicated — you tune its quantity instead.

<ComponentPreview
  name="transfer-picker-multiple"
/>

Key points of the assembly:

- Selecting an existing value is a no-op; quantities are tuned per entry with `<NumberField variant="embedded">` (positive integers, clamped to `1–99`) — the borderless inline steppers keep the row compact.
- The header checkbox shows the total quantity next to the label (`Selected (total)`), summed across entries.
- Everything else matches the plain variant — same remote left panel, same batch removal.

### With Popover

Wrap the panel in a [Popover](/docs/component/popover) to get the MultiSelect-style delivery: the trigger button shows the selection count, the panel opens beneath it, and `Stash` / `Confirm` close it.

<ComponentPreview
  name="transfer-picker-popover"
/>

Key points of the assembly:

- The Popover trigger renders a constant-shaped label `` `Options (${selected.length})` `` so its width stays stable and avoids layout shift.
- Popover's `open` / `onOpenChange` control the panel; reset the `highlightIndex` when it closes, and let `Stash` / `Confirm` call `setOpen(false)`.
- The keyboard handlers guard on `open` so arrow keys only navigate while the panel is visible.

Refer to the [List API](/docs/component/list), [Input API](/docs/component/input), [Checkbox API](/docs/component/checkbox), [NumberField API](/docs/component/number-field), [Popover API](/docs/component/popover) and the `useRemotePagination` hook for the full prop tables.
