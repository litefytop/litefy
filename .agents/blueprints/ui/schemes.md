# 方案令牌（app/ui/schemes/<slug>/index.css）

1. 色板每方案 24 枚、亮暗各一套：画布的背景与文字 `background` / `foreground`、次要容器的背景与文字 `surface` / `surface-fg`、强调背景与文字 `accent` / `accent-fg`、边框 `border`、品牌三件 `primary` / `primary-fg` / `primary-accent`、语义四族 `danger` / `info` / `success` / `warning` 各三件（背景色、`-fg` 前景色、`-accent` 悬停背景档）、禁用背景与文字 `disabled` / `disabled-fg`。禁用对独立取值，不随品牌或表面色板换色，供各组件的禁用变体共用。每一枚背景令牌与一枚前景令牌同档成套，成套律与禁衍生见第 24 条。色板之外不设颜色令牌；浮层背景、焦点环与独立状态前景别名是方案机制值，由这 24 枚派生。焦点环全局唯一，写在 `index.css` 的 `--focus-*`：minimal 为 1px `primary` outline 加 3px `primary` 50% 透明的阴影，invalid / danger 组件转 `danger-fg` 及其 50% 透明的同形阴影；neo 无透明度，为 2px `foreground` outline；flat-minimal 亦无阴影 glow，为 2px `primary` 实线 outline（offset 2px），invalid / danger 转 `danger-fg` 同形；neon-gradient 随画布分档（第 16 条）：日 2px cyan-700 实线加同族柔影、danger 转 rose-700；夜 2px cyan-400 实线加 cyan 光晕、danger 转 rose-400。
2. 后缀只有两枚：`-fg` 是前景色，`-accent` 是强调 / 悬停背景档；背景色一律不带后缀，`@theme` 同形（`--color-surface` / `--color-danger`）。画布例外用全写 `background` / `foreground`。
3. 语义四族成套取用：`<status>-fg` 是状态块上文字色，`<status>` 是状态静置背景色，`<status>-accent` 是强调 / 悬停背景档；取值归方案、逐枚字面定色（禁衍生见第 24 条），下述深度档只作设计描述：`<status>` 300 / `-accent` 200 / `-fg` 900，亮暗两档同值（用户定 2026-11-25：语义块背景夜间不再翻亮一档——夜档拿 200 档做静置背景会让粉彩块过浅，与日间对不上；`.dark` 不声明语义四族任何一枚，`:root` 单源作答；minimal / neo / flat-minimal 同构同值，neon-gradient 两档同答霓虹值（只有背景三档分档，见第 16 条））；块上文字 `-fg` 对 `<status>` 与 `-accent` 实测 5.24–7.49:1（AA 过，第 24 条要求的静置与悬停两档都在此区间，实测值）；填充对 `surface` 亮档不足 3:1（约 1.3–2.2:1）是既接受项——1.4.11 只约束理解内容所必需的视觉信息，进度 / 量具缺省尾随可见读数（值有文本替身）后填充即非必需图形，量具类不强制 1:3（用户定则）；独立语义文本与图标不落在语义块上时挂 `text-<status>-independent`，读取方案机制值 `--text-<status>-independent` 并对实际背景实测 AA；minimal / neo / flat-minimal 亮档读 `<status>-fg`（900 档深字）、暗档读 `<status>-accent`（200 档浅值——背景档冻结后夜档文字亮度不变，实测值见各案 design.md 对比度节），neon-gradient 夜档读 `<status>`、日档读同族 800 档字面（第 16 条）。皮肤按 `bg-<status>` + `text-<status>-fg` 成对写；独立状态文字、图标与边框统一挂 `text-<status>-independent`，由各方案按实际背景映射，不与状态块前景色共用。
4. `@theme` 的色彩映射只答这 24 枚色板（`--color-<令牌名>` 同形一一对应，清单见第 24 条）与浮层成对槽 `--color-surface-raised` / `--color-surface-raised-fg`与独立状态文字机制别名 `--color-<status>-independent: var(--text-<status>-independent)`，其余颜色槽位（`panel` / `quiet` / `plain` / `active` / `block` / `field` / `note-*` / `shell-*` / `hover` / `paper` / `veil` / `black` / `white` …）缺省不设——确有必要时先修订本条把槽位纳回色板（枚数随实际开放数同步），恢复后即可正常取用，未恢复前的存量消费由整库重写处理；焦点轮廓（`--focus-outline-*`）与阴影档不是颜色变量，不在此律内；浮层与内容容器背景机制值 `--color-surface-raised`（rule 1 派生，亮暗两档一律答「比画布更凸一档」的独立档：亮档答纯白、暗档答比画布抬亮一阶的独立具名阶（minimal 灰 800、flat-minimal sky 800、neo 近黑 `oklch(20.5% 0 none)`），不再同档引用 `surface`；阶梯与逐案实测值见 `ui/schemes/elevation.md`，分层律见第 21 条）与它的配对前景 `--color-surface-raised-fg` 自 2026-11-25 起组成「成对机制槽」——两枚都进 `@theme` 映射、都受第 24 条成对律（`surface-raised-fg` 对 `surface-raised` 日夜各 ≥4.5:1）约束，但不受禁衍生约束（`surface-raised` 允许同档引用 `var(--surface)` 一类别名）；它们不计入 24 枚色板。背景填充走全案同构 fill 契约，四案都声明同构 `bg-*` 家族（`bg-background`、`bg-surface`、`bg-disabled`、`bg-primary` / `bg-primary-accent`、`bg-accent`、语义四族 `bg-<status>` / `bg-<status>-accent`），本体固定两行：`background-color: var(--color-<角色>)` 纯色兜底 + `background-image: var(--fill-<角色>, none)`；`bg-disabled` 的 image 通道固定 `none`，覆盖彩色按钮原有渐变。豁免档 `bg-primary-solid` 同入家族、四案同构：本体答 `background-color: var(--color-primary)` + `background-image: none`，专供小面积图标类指示器挂用（Checkbox / Radio 指示框、Timeline 圆点——渐变要有充足空间，16px 级图标盒内 200% 填充只剩硬切两半，用户定 2026-11-22）；纯色案与 `bg-primary` 渲染同效，渐变案以它为小图标渐变豁免通道。填充机制变量 `--fill-<角色>` 在各案 `:root` 答值：纯色案答 `none`（渲染与无填充一致），渐变案答整段 background-image——角度、stop 数、尺寸、流动动画都是值的一部分，渐变案 design.md 的 `gradients:` YAML 即其答值来源（rule 7 同律）。变体组合（`hover:` / `active:` / `has-[:checked]:` / `data-[…]:`）复用同一 utility 本体，全部状态自动同填充；悬停换档沿用 `-accent` 档 utility，渐变案要同图流动就答 `--fill-<角色>-accent: var(--fill-<角色>)`（图像同值、尺寸保留，position 滑动由案内 utility 追加行表达）。组件私有颜色通道（运行期换色的填充，Progress / Meter 弧色一类）接渐变时按同契约成对持 image 通道读同族 `--fill-<角色>`（Progress / Meter 弧色：`--litefy-arc-fill` 随 data 状态指向对应 `--fill-*`，皮肤本体写 `background-image: var(--litefy-arc-fill, none)`），纯色案答 `none` 自动回落纯色；与图表共用色通道的件（MeterGroup 段色）不接填充、保持纯色（用户定 2026-11-22）。文字填充：组件需要渐变字时挂 `text-fill-<角色>` utility，本体固定三行——`background-image: var(--text-fill-<角色>)`、`background-clip: text`、`color: transparent`；文字填充没有 `none` 档，纯色案答同色渐变兜底；渐变字与 `text-shadow` 互斥，允许渐变字的角色由各案 design.md 自答。边框不设填充车道：边框与描边一律读纯色令牌，渐变边框需求出现时另立蓝图任务。令牌本体保持纯色：文字、描边、焦点环、阴影与派生仍读它。原生滚动条部件可加渐变 thumb 并去除原生箭头。
5. 运行期换色只重指向色板内令牌：`[data-brand]` 等属性档只重答 `--primary` / `--primary-accent`（品牌三件中 `--primary-fg` 由 `:root` / `.dark` 单源作答，不随档变）；`[data-surface]` 答次要容器背景与 `accent`；同一方案内 `accent` 只归一个属性档答，不得两属性并持。minimal 开 `[data-brand]` / `[data-surface]`；neo-brutalist 开 `[data-brand]` 与 `[data-accent]`（答 `accent` / `accent-fg` 两件），不设 `[data-surface]` 梯——画布与次要容器是它的身份，不交出去（第 23 条）；flat-minimal 开 `[data-brand]`（用户定 2026-11-26，原「固定色不设梯」作废），答品牌三件加 `--accent`——悬停车道随品牌同色相派生（用户定 2026-11-26）：日档答 `oklch(82.8% 0.09 <该档日 primary 色相>)`、夜档答 `oklch(37.9% 0.078 <该档夜 primary 色相>)`，L/C 锚定原固定字面只换色相，`--accent-fg` 同 `--primary-fg` 单源由 `:root` / `.dark` 作答不随档变；默认档悬停色相随之从 224 归入 240.876（原字面退役，观感变化在 C 0.09 低彩下不可辨）。画布与表面保持冷灰蓝身份色，不设 `[data-surface]`。neon-gradient 摘出发品位，不设梯。
6. 一个角色名只能属于一个 `@theme` 命名空间：`--color-x` 与 `--border-width-x` 同名时 `border-x` 同时生成宽与色两条规则，色档按源序抢掉写在它前面的 `border-border`。边框宽度档只有 `control` / `hair` / `frame`；例外：连续条 / 倒计时内条的前景细描边走原生 `outline-1`（1px、四案同值、画在盒外不占填充——hair 档随案 1–4px，且盒内 `border` 会吃掉 4px 内条的填充）。
7. 各套方案逐档同值：`index.css` 的 `@theme` 是该方案 `design.md` YAML 数值的实现，两边不一致时以 YAML 为准并报告冲突。
8. `index.css` 六块定序，一块一职责；`index.css` 是纯主题层，入口接线（`@import "tailwindcss"` 与扫描源 `@source`）归消费方 Tailwind 入口，不在方案文件内（分发模型 B，见 distribution/cli.md 第 13 条）：① `:root` / `.dark` 令牌与机制值，`--litefy-scheme` 只在此声明一次，组件运行期变量（cascader 深度/列宽这类）不进 `index.css`；② 运行期 ramp——minimal 的 `[data-brand]` / `[data-surface]`、neo-brutalist 的 `[data-brand]` / `[data-accent]`、flat-minimal 的 `[data-brand]`（第 5 / 23 条），neon-gradient 摘出发品位不设；几何令牌恒定律见第 11 条；③ `@custom-variant`（`dark` / `quiet` / `plain` / `borderless` / `bordered`/ `motion-safe`——双分支：OS `prefers-reduced-motion: no-preference` 或根元素 `data-motion="full"` 任一命中即动，站内「完整动态」对 CSS 呼吸类动画有覆盖权（动效指南契约）；独立消费方根元素无 `data-motion` 时退化为纯 OS 查询，行为不变）；④ `@theme`——色彩先 `--color-*: initial` 再只映射 24 枚与机制值 `--color-surface-raised` / `--color-surface-raised-fg`，控制几何 `--height-control` / `--height-field` 同值 2.75rem（按钮与行控件同读控制令牌，按钮不骑数字乘道——乘道随 `--spacing` 逐案缩放会让 neo 按钮与 44px 控件车道断档），行控件反解 `--padding-tight` / `snug` / `loose` 三档，卡面内边距 `group-seam` / `field-seam` / `field-invalid` / `pure-icon` / `motion-frame` / `lift` / `crush` / `press-frame` / `shadow-frame` 系 / `shadow-block` 系 / `shadow-surface` / `shadow-checked` / `focus-ring-danger`/ `thumb-hit` / `line-cap` / `line-join` / 排版单挂家族 `typo-h1`~`typo-h6` / `typo-headline` / `typo-kicker` / `typo-body` / `typo-quote` / `typo-list` / `typo-code` / `typo-link` / `typo-overline`——约定见 schemes/typography.md 蓝图；键帽形态类 `kbd`——约定见 schemes/kbd.md 蓝图）；骨架脉冲不设自定义 utility——走核心模板 `animate-pulse`，minimal 与 flat-minimal 用核心档，neo 在 `@theme` 重答 `--animate-pulse` 为硬切两档；⑥ `@layer base`——长文作用域、边框默认色、字体、`data-motion` 动效开关；`@property --litefy-cols` / `--litefy-percent` 随用随注册。禁用观感不设全局 `:disabled` / `[inert]` 规则（多库同屏不越界）：皮肤为正常态与禁用态分别定义类串，已知禁用状态时以禁用类串替换正常颜色、状态与 hover / active 类，保留原有圆角、边框、阴影和布局结构，并显式挂 `cursor-not-allowed`；逐选项组件按每一项的禁用状态分别选类。单容器禁用不使用 `pointer-events: none`；双容器禁用在外层挂禁用背景色、文字色与 `cursor-not-allowed`，内层原生交互件保留原生 `disabled` 并挂 `pointer-events-none`。两类禁用都不额外渲染包裹层或副本，不用 `inert` / `dim` 代替禁用样式，也不使用 `hover:not-disabled:` 等排除式门控。原生控件使用原生 `disabled`；自定义交互控件的 `aria-disabled` / `data-disabled` 必须配合 JavaScript 阻断点击、键盘和导航动作。态色（`aria-selected` / `aria-[checked=true]` / `data-[range=…]` 等）与单纯 hover 同特异性 (0,1,0)，靠源序（态选择器居后）压过 hover，无需反制门控；需压过态色的复合 hover（如 checked-hover）挂 `hover:aria-[checked=true]:` 这类 (0,2,0) 复合变体。按压反馈不设全局 `button:active`：按压由各皮肤显式挂 `active:` utilities（`crush` / `shadow-frame-active`），未挂即无按压。

1rem))`，不设固定最小宽；Dialog 默认 28rem、Drawer 默认 24rem，保留既有大档与贴边形态。固定形态控件、Toc 固定栏、真实纸张与图表 / 表格等内部结构尺寸按各自车道保留。排版类常量不带宽度，宽度由消费处显式挂，避免同元素两枚 `max-w-*` 按源序互相覆盖。唯一 em 例外是正文行宽 `max-w-[40em]`——它要随字号走而不是随栅格走（中文 40 字 / 拉丁 80 字符，a11y 下限见 ui-rules `perceivable.md` 19）；定档件分两基：容器级（浮层 / 面板 / 页面块）一律 16n 单位，控件级小容器（步进器、值区、页码输入一类）一律 11 的倍数——`w-11` 是触控目标基准（全端恒定，默认案 44px，2.5.5 AAA），各案按自身 `--spacing` 定值、不随视口或指针收缩，小容器不再另立第三档；浮层宽度对视口负责不对父格负责，车道与选道顺序的正本在 delivery `references/skin-rules.md` 第 16 条。浮层面板是小卡片档：圆角取 `rounded-md`，内边距自带圆角补偿 `p-[var(--radius-md)]`（= 面板圆角档，角弧整体收进内边距内，内容不被角弧裁剪；无圆角方案自然归零、行贴边；用户定 2026-11-22）。补偿值不设跨文件共享变量，各组件面板串内联自带——每个组件的面板只并一个变量，禁两变量合并；Popover 容器本体维持零内边距契约（外壳不取），command 面板是对话框卡、保留 Dialog 原生 `rounded-xl` 与 `p-4`（行距边 16px，角弧侵入约 0.29×圆角 ≈ 7px 不裁），日历 `p-3` 自有律不变。浮层内嵌列表律（用户定则）：圆角只归浮层面板，内嵌列表视口不设自身圆角、不继承面板圆角，行 hover 由面板内边距兜住不被角部裁剪；无圆角方案归零、行贴边。

24. 色板成对律、禁衍生与状态档配对书写（用户定 2026-11-25，同日修订一次）：
    成套——色板 24 枚加浮层成对槽一枚，每一枚背景令牌与一枚前景令牌同档成对：`background`↔`foreground`、`surface`↔`surface-fg`、`surface-raised`↔`surface-raised-fg`（成对机制槽，不受下段禁衍生约束）、`accent`↔`accent-fg`、`primary`↔`primary-fg`、`disabled`↔`disabled-fg`、语义四族 `<status>`↔`<status>-fg`；`<role>-accent` 悬停档不单设前景，由主体 `<role>-fg` 兼任（所以它必须两档都过）。**补全律**：只答了一枚颜色的令牌不合法——缺 `-fg` 的按本条新增一枚（连带 `@theme inline` 映射与 design.md 去处条目，色板枚数同步），不许靠继承 `foreground` 或省略来凑；反过来纯文字的令牌（`text-<status>-independent`）必须声明它压在哪些背景档上并逐档实测。达标是令牌层责任，不是皮肤层：同一枚 `-fg` 对该角色的静置背景与 `-accent` 档，两档都实测 ≥4.5:1（AA 硬下限、不进位，见 ui-rules `perceivable.md` 3；本条只对文字位取 4.5，图形位 3:1 随该条原律）。不达标就改背景档取值或改配对前景档取值，禁止就地调透明度、禁止用阴影糊。
    禁衍生——色板令牌在 `index.css` 只答字面色值（hex 或 oklch 三元组）：不写 `color-mix()`、不带 alpha 斜杠、不指向另一枚色板令牌；「深一档 / 浅一档」直接写死那一档的值。机制值不受本段约束——`--border` 透明档、`--focus-*`、`--elevation-*` 的品牌染色层与 `--text-<status>-independent` 别名照旧运算（第 1 / 4 / 15 / 19 条），运行期换色时随品牌自动跟随。
    状态档配对——皮肤换哪一档背景，就同时写那一档的配对前景：`hover:bg-accent hover:text-accent-fg`、`data-[state=active]:bg-primary data-[state=active]:text-primary-fg`、`aria-pressed:hover:bg-primary-accent`（同族悬停档共用主体 `-fg`，故不再补第二枚文字档）、`active:` / `data-[dragging]` / `focus:` 同理。成对写之后**文字档不再分日夜**——同一串在两档都成立，这才是「不需要切换」的确切含义：不需要按档位猜该用什么文字，不是可以不写文字。继承文字（`text-inherit`、消费者传色、运行期数据色）不在成套律覆盖内，落到底色档上时必须显式写该档 `-fg`。两条越界禁令保留：角色色当文字用不越界——`primary` 文字压 `accent` 实测 2.73 / 3.43、压 `background` 3.9（neo 实测值，均不过 AA），所以文字标签族只在同族背景上上色（Tabs 线型变体的悬停底档只给 `data-[state=inactive]`，选中页签靠 `border-b-primary` 与字色发声）；填充态悬停留在自己角色族——`bg-primary text-primary-fg` 的件悬停换 `primary-accent` 而非 `accent`（`primary-fg` 压 `accent` 实测 1.3–1.9，压 `primary-accent` 本案日夜 9.69 / 10.69）。第 19 条的「`surface-fg` 只配实际 `surface` 填充」让一步：静置铺 `surface` 的行（斑马纹表行）悬停换到 `accent` 时文字改读 `accent-fg`，不留在 `surface-fg`——`surface-fg` 对 `accent` 在夜间是 1.77（米白压黄，实测值），换配对才两档都成立。
    车道可辨——悬停档必须真的看得见：`accent` 对它可能压上的每一枚静止背景（`background` / `surface` / `surface-raised`）OKLab 距离 ≥0.08；同族深化档 `<role>` → `<role>-accent` ≥0.06。彩色方案（neo-brutalist / neon-gradient）的 `accent` 本身必须是彩色档（OKLCH 彩度 C ≥ 0.08）——夜间把悬停档答成近中性深色（`#38342b`，C 0.016，与画布距离 0.116 却同为低彩暖棕）就是这一条在防的事：成套比值全过、悬停却看不见。中性灰阶方案（minimal / flat-minimal）以明度步替代彩度：`accent` 对静止档 ≥8 个 L 点。
    品牌档位——`primary` 不强制日夜双档：两档同值（固定单档）或分两档，各案自答，逐档过成套；本案（neo-brutalist）分两档且与 `surface` 色相对调（第 20 条）。
    门禁——`scripts/check-color-pairs.mjs` 入 `types:check`：解析各案 `:root` / `.dark` 色板段，核字面性、配对完整性（缺 `-fg` 即报）、成套比值、悬停车道距离与彩色同构（彩色案的夜间彩色档集合不得比日间掉档），未过即报错；仍在迁移中的方案把违规枚登记进带原因的豁免名单（同 `check-ui-css.mjs` 写法），Neo 之外的案逐案移出。

25. neo-brutalist 成对答值（用户定 2026-11-25，取代同日的「固定单档 + 暖深色板」答值）：`--primary` 日答粉 pink-700 `oklch(52.5% 0.223 3.958)` + `--primary-fg` 白 `#ffffff`（静置 6.11），悬停 `--primary-accent` 加深到 pink-900 `oklch(40.8% 0.153 2.432)`（白字 9.69，道距 0.136）；`--surface` 日答酸橙绿 lime-300 `oklch(89.7% 0.196 126.665)` + `--surface-fg` 纯黑（16.12，先前的 `#1a1a1a` 一并转正）。夜间对调：`--primary` 答那枚 lime-300 + 黑字（16.12），`--primary-accent` 答 lime-500 `oklch(76.8% 0.233 130.85)`（黑字 10.69，道距 0.135）；`--surface` 答那枚 pink-700 + 白字（6.11）。`--accent` 日夜同值 yellow-300 `oklch(90.5% 0.182 98.111)` + `--accent-fg` 黑 15.91，是本案唯一的行为强调面，夜间不许转中性（上轮答 `#38342b` 使道距掉到 0.116 且彩度只剩 0.016，行悬停在黑画布上看不见，已由第 24 条车道可辨律拦住）。新增第 25 枚 `--surface-raised-fg`：日黑（压纯白 21.00）/ 夜白（压 `oklch(20.5% 0 none)` 17.91）。画布反转：夜 `--background` 纯黑、`--foreground` 纯白、`--border` 白（对画布 21.00 / 对表面粉 6.11 / 对浮层 17.91），夜 `--disabled` `oklch(26.9% 0 none)` + `--disabled-fg` `oklch(70.8% 0 none)`（5.83）；语义四族日夜同值（第 3 条），同一枚 `-fg` 压静置与悬停两档实测 `danger` 5.24 / 6.94、`info` 5.74 / 7.31、`success` 6.49 / 7.49、`warning` 6.57 / 7.47（实测值）。悬停车道实测：日 `background`→`accent` 0.177、`surface`→`accent` 0.095、`surface-raised`→`accent` 0.205；夜 0.923 / 0.483 / 0.723（OKLab 距离）。两处已知冲突，按边界处理不硬修：夜间白描边压黄悬停面 1.32、夜间独立状态文字（读 200 档浅值）压黄面 1.08–1.14——凡此二者出现在可悬停面上，皮肤写 `hover:text-accent-fg` / `hover:border-accent-fg` 把该面前景整体转到黑，黄面不再挂第二色。成套后本案全部背景↔配对前景落在 5.24–21.00。

26. 风格收敛律（用户定 2026-11-26）：每套方案 = 共享骨架 + 基础值 + 签名特征；签名之外的令牌一律回归基础档（minimal / flat 的同构值）。排版节奏类参数——间距基数 `--spacing`、行高阶梯、全局默认字体、标签大小写 `--text-transform-label`——不承载风格、全案同构，风格的杠杆在签名角色令牌与色板。签名特征限形态类，每案 2~5 项、登记进各案 design.md prose 签名清单节；签名特征不开放运行期换色（第 5 / 23 条锁件清单）。neo-brutalist 签名五项：硬偏移纯色阴影（静置 4px / hover 6px 档）、2px 实线边框、零圆角、yellow-300 悬停强调档（日夜同值）、夜间画布反转与粉绿对调（第 20 / 25 条色值）。minimal / flat-minimal 维持既有形态不变。新增方案先列签名清单再填值（new-scheme 技能步骤序）。

27. 阴影足迹上限（用户定 2026-11-26，覆盖第 15 / 16 条的大模糊取值）：所有模糊投影的可见足迹（模糊半径 + 位移）收在 24px 以内，四端同一套值，无媒体 ramp——手机、平板、窄窗与桌面读同一套令牌，不因视口或指针分档（第 11 条几何恒定律延伸到机制值）。依据：移动端内容区左右各 16px（`px-4`）、预览舞台 8px（`p-2`），投影扩散超过留白即被容器裁切；不为投影预留额外留白（会压缩内容宽度），改由缩档解决；层级读法不靠阴影体量——明度阶梯是主手段（第 21 条），边框与位移共担，缩档后靠模糊半径与不透明度的档差维持四级可辨。neo-brutalist 硬偏移阴影（静置 4px / hover 6px）与 flat-minimal 零投影本就在上限内，签名不动（第 26 条）；minimal 保留三层扩散柔影与暗档同形加倍律（第 15 条），neon-gradient 保留日柔影 / 夜光晕分档（第 16 条），只收数值不改形态。焦点光晕 `--focus-glow` / `--focus-glow-inset` 同受 24px 上限。逐案数值见各案 design.md 的阴影段（`minimal` 在 prose Elevation & Depth、`neon-gradient` 在 YAML `shadows` / `shadows-light` 块）与 `index.css`。
