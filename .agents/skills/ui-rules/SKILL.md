# 路由

1. 下限与复用律住在六个文件里，按触发条件读，不许凭记忆写皮肤
2. `references/component-first.md`——写交互件与卡片前读：组件库优先复用，禁原生件与手写仿件，静态件禁 hover
3. `references/perceivable.md`——定颜色、字号、动画、图形替身前读：对比下限、文本替代、缩放、减动效与闪烁
4. `references/operable.md`——定交互结构前读：键盘通路、焦点顺序与遮挡、命中区与外扩、指针手势替代、悬停浮层
5. `references/understandable.md`——写表单、分组、向导、文档站正文前读：标签与说明、错误三件套、结构语义、一致命名
6. `references/robust.md`——在 `role`、`aria-*` 与原生件之间做取舍时读：名/角色/值、live region、`data-*` 与 `aria-*` 分工
7. `references/verification.md`——交付前读：键盘走查、无障碍树、实测尺寸、缩放与对比的核法

# 用法

1. 一条链：定车道（哪个文件）→ 对现状（缺口已在文件里标出「未接线」）→ 落进蓝图或皮肤 → 按验收实测
2. 冲突裁决：本技能定无障碍下限（对比比率、命中尺寸、键盘通路等必须达到的底线），方案 `design.md` 定具体取值（颜色、时长、间距等设计值）；取值不得低于下限，两者冲突时以下限为准。系统兜底未接线的地方（`forced-colors`、朗读端默认行为）不许当作已解决
3. 缺口当场补，补不动就在对应蓝图记一行，别在技能里留待办
4. 业务层指文档站外壳、页面与 demo（`app/components`、`app/routes`、`app/demos`），不是 UI 库本体。业务层禁止写原生交互件：`button` / `input` / `select` 一律用 `app/ui/skins` 的封装组件；`div` 不限，`<a>` 穿按钮变体（`buttonVariants`）是许可用法
5. 适配只做大小不改布局（约束业务层与仍在开发的组件）：窄屏与窄容器靠滚动、箭头提示可拖与尺寸伸缩表达；断点、容器查询与运行期测量不切换布局方向、排列、堆叠，这些只由 prop 固定。豁免：蓝图声明双形态、已完整且无后续开发计划的库组件（如 Toc、Pagination）可按断点 / 容器查询切换两套形态，但形态类名必须按形态分离、形态关键槽位不开放消费方覆盖（见各组件蓝图）

# 最小示例

按钮皮肤一条过：命中区 `min-h-control`（44），图标内容随控件文字（`[&_svg]:size-[1em]`），环由方案 `focus-visible:focus-ring`，危险态用 `data-danger` 捕危险环，纯图标件补 `aria-label` 且可见文字要进名字——正本在 `app/ui/skins/button.tsx`。
