# 验收与排障

1. 键盘走查：Tab 走完全序（顺序要等于视觉顺序）、Shift+Tab 回得去、每一步焦点环可见、Esc 关浮层且焦点归还触发件、复合件内方向键走得动
2. 无障碍树核对：DevTools 的 Accessibility 面板逐件看 role / name / state 三件；`aria-hidden` 的节点应当整棵消失，还在就说明落在可聚焦件上
3. 命中区读实测值：用 `getBoundingClientRect()` 量渲染尺寸，不读 CSS 声明——伪元素外扩、`min-height` 与 `padding-block` 反解三套车道都会骗过源码检查
4. 缩放两遍：浏览器文本放大到 200% 跑一遍，320px 视口再跑一遍，看裁字、叠字、横向溢出与遮挡
5. 对比按档核：亮档与暗档分别核正文 4.5:1、大字号与非文本 3:1；状态色单独核一遍，别用亮档的结论套暗档
6. 减动效实测：开系统减弱偏好后动画全停、内容一条不丢；关掉偏好后动画回来——只测一半等于没测
7. 焦点遮挡实测：滚到页面中段再用 Tab 触发焦点移动，确认 sticky 头部与底部工具条没盖住焦点件
8. 临时 axe 扫描（可选）：本仓不挂 axe 门禁，需要时用浏览器注入 axe 单次扫 demo 区，只作排障参考，不作交付依据
9. 违规先问车道再修：缺名 → `aria-label` 或 `<label for>`；缺状态 → `aria-*` 而不是新 `data-*`；缺键盘 → 换原生件或补 `onKeyDown`，不是加 `tabIndex`；焦点被遮 → `scroll-mt`；对比不达 → 改配对 `*-fg` 令牌，不在皮肤就地调色
10. 一条违规牵一片：同一车道上的其他组件同批检查（例如按钮环改了要连着看分页、向导、标签页的触发件）
11. 交付记录：门禁第 2 条要求按 `ui-rules` 执行时，把走查过的键位与实测数值写进交付汇报，没测的项标未测
12. 缺口记账：补不动的下限写进对应蓝图一行（例：MeterGroup 轨道与图例均 `aria-hidden`，逐段占比对朗读端不可达，待裁决可访问名称车道），不在技能正文里留待办
