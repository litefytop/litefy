# 可理解（WCAG 3.1 / 3.2 / 3.3）

1. 页面语言由 `<html lang>` 给出（`app/root.tsx:24`）；行内异语言片段（术语、代码、拼音）自己标 `lang`
2. 阅读顺序由 DOM 顺序决定：禁止用 `order`、绝对定位或浮动调换朗读顺序——视觉顺序与朗读顺序不一致就是缺陷
3. 标题不越级、不空标题：`h1 → h2 → h3` 依层级下探，装饰用的大字号走 `typography` 类而不是假标题
4. 地标要有名：同页多个同类地标（侧栏 `nav`、顶栏 `nav`）各写 `aria-label`（`docs-shell.tsx` 已这样做）；`main` / `header` / `aside` 只承担各自职责，不许混用 `div` 冒充
5. 列表与表格用结构标签：多项内容用 `<ul>` / `<ol>`；数据表用 `<th scope>`，可排序列补 `aria-sort`（`table.tsx` 已接），表说明走 `<caption>`（`table.tsx` 已接 `caption` prop 与槽位，表头 `table` 渲染）
6. 控件必有标签：`<label for>` 关联控件（`field.tsx` 的 label 节点）；纯图标件写 `aria-label`；`title` 与 `placeholder` 都不算标签
7. 说明与错误挂在控件上：`aria-describedby` 指向提示节点（`field.tsx` 的 `hintId` / `alertId`），不靠相邻摆放；提示文案要说明格式与必填，不能只有星号
8. 可见文字要进名字：`aria-label` 必须包含按钮上可见那段文字，语音用户念出的名字与屏幕显示不一致即失败
9. 分组语义：选项组用 `role="radiogroup"` / `role="group"` 加 `aria-label`（`radio.tsx`、`checkbox.tsx`、`segment.tsx`）
10. 输入目的要标注：登录、邮箱、电话、验证码这类字段要写 `autocomplete`（`input-otp.tsx` 给 `one-time-code`；`Input` 按 `type` 缺省 email/tel/url/search，`Password` 缺省 `current-password`，均已接，外部值优先）；类型用 `type` 与 `inputMode` 表达，不靠占位符暗示
11. 错误三件套：识别（`aria-invalid` + `role="alert"`，`field.tsx`）、定位（说清哪个字段）、建议（怎么改，如「需 8 位以上」）；只把边框标红不算报错
12. 高风险动作要可撤销或先确认（删除、放弃修改、清空）：走 `data-danger` 按钮并配确认或撤销路径；表单超时不许静默丢数据
13. 一致命名与一致呈现：同一动作全站同一叫法，同一角色组件的外观钩子与属性名一致；文档站的「复制代码」「查看源码」这类按钮词不许一处一套
14. 帮助与状态入口位置一致：同类控件的帮助链接、错误位置、加载提示放同一处，不按页面各自发挥
15. 重复输入要省掉：多步流程把已填内容带下去（`wizard` 的状态是车道），搜索与筛选条件在返回时保留
16. 同屏竞争性选项要收敛：并列可选项越多决策越慢（希克定律），但不写死「每屏 ≤N 项」——项数由任务定。做法是渐进披露（常用项直出、其余进二级）、给推荐项或默认值、用语义分组与组眉把长列表切段（`menu` / `command` 的分组车道）；默认值必须是安全的那一个，破坏性动作不做默认
17. 记忆负担靠识别不靠回忆（米勒定律同样不写死项数）：已选值、当前筛选、上一步结果要留在屏上可见，不要求用户记住跨屏信息；分步流程给进度与回退入口
18. 状态矩阵三态必答：完成态、错误恢复、加载完成——有异步或提交流程的件都要答出这三态的可见反馈与朗读出口。完成态给明确结果而不是静默关闭；错误恢复保留已填数据并说清下一步（第 11 条三件套）；加载完成撤 `aria-busy` 并播报结果（`robust.md` 7、9）。用户记住的是峰值与结尾（峰终定律），结尾静默等于把体验交给运气
