# 源码变更

1. 源码必须按蓝图执行；皮肤按 `ui/skins/<name>.md` 施工，方案取值看各方案 `design.md`
2. 源码禁止注释，参数语言默认英文
3. 文字色取与背景色配对的 `*-fg` 令牌；只有背景色来自运行期数据（消费者传色、图表序列色、图片压字）的槽位才用 `contrast-color()`，不用它替代现成配对
4. 命名只用通用、正式的词汇（设计系统与 CSS 通行词，加既有后缀 `-fg` / `-accent`），禁止自造词，也禁止用简写代称——背景色、前景色一律写全，不写「底」「墨」一类简称；一个语义只许一个名字——既有族能表达的不许新开前缀或新起族名
5. 写或改任何皮肤串前读 `skin-rules.md`：通用外观律，方案无关、全库一份
6. 布局稳定律：重排由样式与内容变化触发、与结果尺寸无关——切换态组件（tabs / 分段 / 步进器 / 轮播 / loading 态）外框尺寸恒定，用 `min-height`、固定 grid 轨道、预留道、`h-full` 拉伸等纯 CSS 声明钉死，把内容变化的重排圈在盒内并保零位移；确需尺寸变化时，让变化落在已钉死尺寸的祖先之内，或以 `transform` / `opacity` 呈现；禁 JS 测量写回尺寸（强制同步布局）
7. 单点合并律：一个元素的最终 class 串在挂载路径上只允许过一次 `cn`——皮肤合并后的串到骨架只许透传或 `filter(Boolean).join(" ")`（checkbox / button 骨架先例），禁止在外层再次 `cn`；同一串也不许经槽位折叠与透传两路重复挂上同一元素；模块层用 `cn` 构造变体常量不计入挂载路径
8. 状态单极律：布尔状态只给其中一极写样式，另一极回落无样式的默认值——先查状态真假两极是否都显式声明了样式，若一极与默认值一致，反转语义取补命名，把样式挪到非默认一极，禁写例外态撤销默认态的覆盖类（如「是否拖动」反转为「是否静止」，动画令牌只挂 static 态，拖拽期间令牌缺席即无过渡，不写 `data-[dragging]:transition-none` 一类取消式覆盖）；减动效契约的 `motion-reduce:*` 不属此类

# 门禁

1. 检查源码是否0警告、0错误
2. 组件需要无障碍检查时按 `ui-rules` 技能执行（皮肤读 `operable.md` 与 `robust.md`，交付读 `verification.md` 走查）
3. 这是React19组件，禁止使用React18 API(比如forwardRef,在React19中已被废弃，ref是props的一个属性)
4. 改 skins 类串后运行中的 dev server 可能不重建 Tailwind 产物（`@source` 扫描缓存）——页面无反应先重启 dev server 再排查，不要误判为代码问题

# 组件维护链

改动通常是一条链，改了上游就要逐环检查下游，不许只改一环：

源码（骨架/皮肤）→ 源码门禁（`pnpm types:check`、lint、新增/改名组件同步 registry）→ 文档站交付

1. 门禁通过后必须走 `ui-docs.md` 交付 demo/文档，禁止跳过、禁止绕开手写
