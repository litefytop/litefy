# 目录与命名

1. 域判定按"蓝图约束哪份正本"，一份蓝图只写一个域：
   1. `content/` — 内容域：`content/docs/**` 正文与各目录 `_meta.ts` 篇目（写什么）
   2. `site/` — 界面域：`app/components/`、`app/routes/`、`app/styles/` 与站点路由构建配置 `react-router.config.ts`（长什么样、怎么运作）
   3. `ui/` — 库域：`app/ui/` 产品本体，与代码子目录同名（`components/` 骨架、`utils/` hooks、`skin/` 皮肤）
   4. `distribution/` — 分发域：`packages/cli/**` 与生成注册表的 `scripts/copy-registry.js`（发什么、怎么取）
   5. `demo/` — demo 域：`app/demos/**`（组件 demo 正本，供文档页 ComponentPreview 与示例墙消费）
2. `app/ui/skins/` 与骨架同规则按组件镜像：`ui/skins/<name>.md` ↔ `app/ui/skins/<name>.tsx`，只写外观——角色名、槽位与条件态；不写方案取值，不写骨架的结构、状态与行为；各方案 `design.md` 的 Components 只保留该组件的专属令牌
3. 界面域按门禁分三层，不看侧栏层级：`site/shell/` 跨页常驻壳层（改动影响所有路由）、`site/widgets/` 嵌在正文里的交互件（随内容页一起双语验收）、`site/pages/` 独立路由功能页（不进 `_meta.ts`，不进 llms 集合）
4. 文件名取它约束的正本路径：`ui/components/button.md` ↔ `app/ui/components/button.tsx`；界面域功能页按路由命名（`site/pages/tools-color.md` ↔ `/tools/color`、`site/pages/overview.md` ↔ `/docs/overview`）；内容域一篇目一蓝图（`content/guide.md`）
5. 延期与范围外项写在对应蓝图里，不另设待办台账；翻译欠账归 `content/docs/sync.json` 白名单
6. 目标落不进任何域：先补域定义再建文件，不为一次任务临时开目录

# 写法规则

1. 蓝图只写目标态："长什么样、有什么、怎么运作"；不写"从 X 改到 Y / 删除 X / 重写 X"等动作描述，变更记录归 git log
2. 蓝图开工前定稿，施工中只读；发现设计错认：停下 → 改蓝图 → 再施工
3. 进度不进蓝图：记同名 `<领域>.progress.md`（已完成步骤、当前进行、下次切入点、临时施工清单），开工创建、完工删除，完成历史归 git log
4. 篇幅随目标复杂度：简单组件一句话即可，不为凑篇幅扩写
5. 分层域：`ui/components/`、`ui/utils/` 只写骨架（结构与行为），`ui/skins/` 只写外观；"外观交给皮肤"是全局约定，蓝图不重复声明，只在交接接口处（data 标记、槽位）提一句；骨架蓝图不写皮肤的字面值（宽度、颜色、时长）
6. 骨架与皮肤按"行为几何 vs 定值"分界：行为依赖的几何（`display`、grid 流、定位、测量容器、`colgroup` 宽度权重）留骨架，定值（尺寸、间距、字号、颜色、时长）全走 class；只有值必须由内联样式或元素属性表达时才内联，并在蓝图注明原因
7. 纯样式组件（无状态、无行为、无无障碍逻辑）不设骨架，只在 `app/ui/skins/` 存在（如 Badge、Callout、Card），同属无独立骨架蓝图：外观规格写进 `ui/skins/<name>.md`，方案取值写进 design.md 的 Components；其中无自有语义、无槽位、无变体的件连组件封装也不设——类名即约定，`@utility` 声明进各案 `index.css`（kbd 先例，同 typo-* ），语义由消费方书写的原生元素自带；带语义容器或槽位结构的（Callout、Card、Badge）仍以组件存在
8. 组件按四层逐级构建：原子骨架导出最小语义单元（零样式零布局），组合骨架组装原子件并发射 data-* 钩子，原子皮肤逐节点出类常量、只挂在自己那个节点上，组合皮肤组装原子皮肤串并承担根容器；皮肤禁从根用后代选择器（`[&_[data-…]]:` 一类）给骨架自有节点定样式——整形单独例外：包装消费方自由内容（第 10 条）与 svg 吃满（skin-rules 第 8 条）的后代选择器仍许可
9. 未定事项单列"待定项"，不臆测方案；跨领域改造另立蓝图
10. 槽位直渲：骨架渲染调用方内容（children 与 ReactNode 槽）不设只为挂 class 的包装容器；classNames / styles 只暴露给骨架自有元素（有行为语义的槽位容器、内部渲染件）；缺省外观由皮肤的自有默认节点承担，对自由数据的固定整形也由皮肤包装；骨架内部渲染、皮肤无法在外层包装的槽位容器（如 chat 气泡）除外
11. 数值标证据强度，三选一并写出来处：**示例值**（说明用法、可替换）、**经验规则**（设计惯例，无实测背书）、**实测值**（本仓库量出来的，改动要重新量）。时长档、间距刻度、色阶差值一律标注；行业或视频来源的参数标示例值，不写成标准——三者混写会让后来者把示例当权威
