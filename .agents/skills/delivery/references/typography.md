# 排版通用律（字号 / 行高 / 字距 / 中文 / 行宽）

1. 本文件只写方案无关的排版规律：取值看各方案 `design.md` Typography 与 `@theme`，长文作用域机制看蓝图 `ui/schemes/typography.md`，宽度车道看 `skin-rules.md` 第 16 条，对比与缩放下限看 ui-rules `perceivable.md`——已有的律只引用不重复。
2. 字号是有限阶梯，一档一场景：档名是阅读角色（标题各级、正文、说明、标签、眉标、行内代码），不是尺寸表。新增一档必须同时答出「什么场景用它、与相邻档差在哪」，答不出就不加；禁档外任意值（`text-[15px]` 一类）。只有字号表、没有场景归属的阶梯等于没定阶梯。
3. 行高不是全局一个值，与字号反比：字号越小相对行高越大（小字靠行距拉开行），字号越大相对行高越小（大标题行距过大会散架）。本库标题走 `leading-head`、正文走 `leading-body`、控件标签走 `--leading-label`，值由方案自答；禁把同一个 line-height 铺到全部档。
4. 字距逐档有人回答，方向随字号反走：大字号收紧（负 tracking，抵消放大后字间的视觉空隙），克制语言可答 `0em` 但必须显式答过；小字号与全大写标签放宽（`tracking-label`）。字距用 em 相对单位随字号缩放，不用 px 定值，禁皮肤裸写 em。
5. 中文排版参数独立回答，不照抄西文：汉字字面率高（字身框几乎被占满），同字号下视觉比拉丁字母大，中西混排按视觉而不是按字号对齐；标点挤压与中西文间距走 CSS 原生属性（`text-spacing-trim`、`text-autospace`），按渐进增强写——不支持的浏览器忽略该声明、退化为默认排版，禁止用 JS 插空格或改写文本内容实现。
6. 行宽有上限：连续阅读的正文挂 `max-w-[40em]`（`skin-rules.md` 16.1），中文 40 字与拉丁 80 字符同时成立；行宽只挂一次，排版域自身不带宽度。
7. 密度与容器查询必须产生行为变化：紧凑档与 `@container` 断点要真的改变量——内边距升降档、行数、列数、显隐；写了断点却不变任何值等于没写，禁把「响应式」实现成同一套定值换个类名。
8. 光学修正按 `skin-rules.md` 第 17 条：几何对齐不等于视觉对齐，字形基线与图标外框不等高。
9. 自检三条：① 每档说得出场景；② 行高与字距随字号变、不是常量；③ 中文与西文各自的参数都有人回答。缺任一条就是这一层没做完。
